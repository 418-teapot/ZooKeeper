# zwiki 可写性模型与检查器重设计

> 2026-09-14 一次 wiki 摄入与域拆分操作中暴露的工具链痛点汇总，以及经逐
> 项质询确认的改进方案。状态：**方案已确认，待实现**。

## 背景

在一次文章蒸馏（ingest 4 个新页面）和随后的 shared 域三分拆分（迁移 14
个页面）中，zwiki 与 wiki skill 暴露出多个结构性问题：写入位置错误、
`page move` 引用更新不完整、检查器诱导"删链接消警告"的坏行为等。本文记
录痛点清单、第一性原理推导和最终确认的改进方案。

## 痛点清单

### 工具侧（zwiki）

1. **写命令允许省略 root，静默错写** — 所有命令默认
   `~/.zoo/wiki`（安装态），但 ZooKeeper 开发者的工作区是仓库内的
   `wiki/`（bundle 源）。忘记 `--root` 不会报错，而是悄悄写错地方。
2. **`page move` 引用更新不完整** — 只更新 relations 与正文内联链接，
   遗漏 Backlinks 区、`sources:` frontmatter 字段（`supersedes` /
   `superseded_by` / `contradictions` 的 path 字段同样携带路径，同属盲
   区）。迁移 14 页后 check 报出 13 个断裂链接。
3. **Backlinks 同步只加不删** — move 后旧路径的 backlink 残留，且过期
   条目被检查器当成仍存在的页面，产生指向已删除路径的误导性建议。
4. **术语检查噪声与规则死锁** — 术语表取自页面标题的子串/前缀，
   "多 agent""子 agent" 等泛化词大量误报；"首次出现必须链接"与"同一目
   标只能链接一次"叠加后，overview 这类多处提及同一页的文档被逼入只能
   删链接或改措辞的角落。
5. **relations 双重手工表示** — frontmatter relations 与正文内联链接表
   达同一组边却都要手工维护，必然漂移；本轮 35 个检查错误中 22 个是此
   类同步问题。
6. **缺域级命令** — 新建域需手工 mkdir 6 个子目录；`page move` 自动生
   成的域 index.md 是残缺骨架。
7. **`zwiki log` 缺 move 动作** — 迁移只能记为 edit + 自由文本，丢失结
   构化的 old→new 信息。

### Skill 侧

8. **三个 wiki skill 硬编码 `~/.zoo/wiki/`** — 把安装产物当成工作区。
   repo `wiki/` 才是 bundle 源（git 版本化、可评审、随插件分发）；写安
   装态不进版本控制，且会被下次 bundle 安装覆盖。
9. **双 root 无同步提示** — repo 源与安装态并存，写一边另一边静默过期。

## 第一性原理推导

### 问题一：写入路由

用问题的语言回答"写入目标应该由什么决定"：

- **输入**：一条待保存的知识；一个想保存它的人；这个人可见的若干知识
  库。
- **输出**：知识被写入恰好一个知识库。
- **必须恒成立**：
  1. 写下知识的人日后一定能重新找到它——查找不依赖"记得存在哪"
  2. 写入的内容不会被他人或机制的后续操作静默覆盖
  3. 多人共享的知识只有一份权威副本，修改留有历史、可评审、可分发
  4. 仅属于个人的知识不进入共享分发物
  5. 写入时不存在需要猜测的决策——对任何一条知识，当前环境下可写的
     位置唯一

被否决的中间方案（按内容/cwd 启发式判断知识归属、agent 路由写入）违反
第 5 条：归属判断是易错的运行时猜测，猜错的代价是私密知识进团队仓库
或团队知识困死在个人存储。

**结论：归属是域的静态结构属性，不是写入时的判断。**

### 问题二：链接检查

检查服务的对象是读者。必须恒成立的只有：

1. 正文提到的、已有页面的概念，存在至少一条可达通道（导航可达）
2. 页面声明的关联与正文实际的链接表达同一组边（声明与内容一致）
3. 检查不激励劣化正文（作者不需要为满足检查而删链接、改措辞）

现有设计让同一条边存在两个手工表示（relations + 正文链接），必然漂
移，checker 沦为漂移警擦，作者沦为警擦的仆人。

**结论：边只 authored 一次；判断归 LLM，机械归工具。**

## 确认的改进方案

### 可写性模型

1. **位置即声明**：`.teams/` 下的域只读（安装态 bundle）；bundle 源仓库
   的 `wiki/` 整体可写；`~/.zoo/wiki` 顶层域可写（个人域）。零新增元数
   据。分发域只有一份可写权威副本（源仓库），安装态漂移在结构上不可能。
2. **写命令 `--root` 必填**（page create/set/move、log、supersede、
   contradictions apply），去掉默认值——调用方必须显式陈述写入目标；
   读命令保持默认 `~/.zoo/wiki`。
3. **只读域拒写**：对 `.teams/` 路径的写入拒绝并报出所属 bundle 名
   （不在 bundle.toml 加 source 字段）。
4. **新增 `zwiki domain create <name>`**：脚手架 6 个子目录 + 规范
   index.md；同时修复 `page move` 自动生成的残缺 index.md（复用同一骨
   架）。

### 缺陷修复

5. **`page move` 补全所有路径携带位置**：Backlinks 区、`sources:` 字
   段、`supersedes`/`superseded_by`/`contradictions` 的 path 字段。
6. **backlinks 同步增删双向**：Backlinks 区本是自动维护的，清除过期条
   目是安全的。
7. **`zwiki log` 增加 `move` 动作**：结构化记录 old→new。

### 检查器重设计

8. **relations 派生化**：正文内联链接（含 References 区，排除
   Relations/Backlinks 区自身）是边的唯一手工表示；frontmatter
   relations 由 zwiki 从正文链接自动同步，与 Backlinks 同一机制。
   `related_redundant`/`related_omission` 错误类消失。这与 wiki 自身的
   设计原则一致："交叉引用的对称性不应由 agent 保证——确定性程序比
   LLM 更适合重复性机械操作"。
9. **术语表 = 页面标题 ∪ 全 wiki 历史链接文本**（派生而非声明，含通用
   功能词过滤）。每一次 `[措辞](页面)` 都是对该页面称呼的一次声明，随
   写作自动维护、随 move 自动更新。子串前缀不再进表，"多 agent"类噪声
   消失。
10. **检查严格性保留**：首次出现必链接、每目标恰好一次维持报错；重复
    链接报错必须引导正确解法（"移到首次出现处"），消除"删链接消警告"
    的坏激励。
11. **新指称发现归 LLM 判断**：识别"换措辞的指称"是语义判断，不是机
    械匹配——子串匹配的召回率是幻觉安慰。该职责由 ingest/review 流程
    中的 kiwi 交叉引用分析承担；孤立页面检查（零入链）兜底最坏情况；
    `suggest-links` 建议性命令列为可选后续项。
12. **check 对只读区跳过写入式同步**，仅报告。

### Skill 改写

13. **wiki-ingest / wiki-query / wiki-verify** 去除硬编码路径：写操作
    显式给 root（bundle 域 → 源仓库 `wiki/`；个人域 → `~/.zoo/wiki`）；
    读默认 `~/.zoo/wiki`。排查 kiwi-distill 的同类路径假设。
14. **新指称发现的 skill 编码**：kiwi-distill 明确语义级指称识别职责
    （识别换措辞的指称，产出应补的内联链接清单）；wiki-ingest 的
    ACCEPTANCE 增加"新页面应补的内联链接"与"已有页面中提及新知识但缺
    链接的位置"两个方向，Phase 2 写入步骤相应增加应用环节。

## 实现顺序

1. zwiki（方案 1-12，Rust，tools/zwiki），`./test.sh` 验证
2. skill 改写（方案 13-14）
3. 全量验证（zwiki check + 现有测试套件）

## 否决记录

| 方案 | 否决原因 |
|------|----------|
| 按内容/cwd 启发式路由写入目标 | 归属判断是运行时猜测，违反"可写位置唯一" |
| root 自动解析（cwd 向上找 bundle.toml） | cwd 魔法：在任意仓库子目录跑命令会静默写到该 repo |
| 术语检查加 aliases 字段 | aliases 是手工元数据，会漂移且无法枚举自然语言指称 |
| 术语检查降级为非阻塞警告 | 丢失严格性：统一链接约定与新边发现能力 |
| bundle.toml 增加 source 字段 | 拒写只报 bundle 名即可，少一份维护的元数据 |
