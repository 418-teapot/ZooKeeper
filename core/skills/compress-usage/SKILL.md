# Compress / Decompress 使用规程

本技能用于在上下文过长、历史已完成一个独立主题，或需要重新查看已压缩内容时，正确使用 `compress` 和 `decompress`。工具会校验保护区、范围边界、工具调用配对、已有压缩块和压缩收益；不要试图绕过这些检查。

## 快速决策

- 需要为后续工具结果和工作腾出空间，且某段历史已经完成一个独立主题：使用 `compress`。
- 需要已压缩主题的精确原文，且对应 block 仍为 active：使用 `decompress` 恢复。
- 只需要已压缩主题的结论：先读当前可见摘要；只有需要索引行背后的旧摘要时才调用 `decompress`。对 active block 调用会恢复原文，不能指定只读摘要。
- 正在执行一个不可中断的原子步骤：先完成该步骤，再压缩其他已结束的历史。需要逐字使用的内容保留原文；未验证结论可以总结，但必须明确标注未验证。
- 压缩和原文恢复会改变压缩状态；相关调用串行执行，多段压缩优先合并为一次 `ranges` 提交。

## 地址规则

### 消息 ref

`compress` 使用当前轮次视图中实际显示的消息地址，例如 `[m2]`。调用前必须从当前上下文重新读取这些地址：

- `fromRef` 和 `toRef` 都是包含边界；`m2` 到 `m5` 包含 `m2`、`m3`、`m4`、`m5`。
- ref 是当前视图地址，不是永久消息 ID。压缩、解压或新一轮上下文变换后，`mN` 可能重新编号。
- 不要凭记忆编造 ref，也不要复用上一轮的 `mN`。旧编号可能仍合法却指向其他内容，工具不能替你识别这种误选。
- 端点落在压缩块的 summary 行时，会覆盖该 block 代表的整个范围，而不是只覆盖一行。
- 首条用户消息、末尾保护区以及工具明确保护的内容不能压缩；如果工具返回保护边界错误，按错误提示缩小范围。

### 压缩 block ID

`decompress` 使用持久的 block ID，例如 `b3`。只使用当前上下文中看到的 block ID：

- active block 通常显示为 `[Block b3 · K 条]`。
- 被更大范围消费后的 block 可能显示为 `--- b3: 标题 ---` 索引行。
- 只接受 `b` 加正整数，例如 `b3`、`b12`；不要传 `3`、`b0` 或自行猜编号。
- block ID 跨轮次稳定，但 block 的状态可能改变；调用结果取决于当前状态。

## 什么时候压缩

压缩前先确认以下各项：

1. 范围已经完成一个独立主题，而不是正在进行的当前步骤。
2. 范围外的后续工作不需要逐字引用其中的代码、报错或对话。
3. 范围内的结论、约束、文件路径、验证状态和未完成事项都能写入摘要。
4. 范围没有切断工具调用与对应工具结果；两者必须一起压缩。
5. 范围没有部分覆盖已有 active block；要么完整覆盖该 block，要么避开它。
6. 多个范围彼此不重叠，并且每个范围是独立主题。
7. `summary` 明显短于原文，能够带来实际空间收益。
8. `fromRef` 和 `toRef` 都来自当前可见视图，且起点不晚于终点。

不要为了满足 nudge 而压缩当前正在使用的上下文。nudge 提供的可压缩窗口只是可选范围，不要求全部压缩；在窗口内选择一个能安全总结的连续子范围即可。

## 调用 compress

参数必须是一个包含非空 `ranges` 数组的对象。每个范围必须包含四个字符串字段。以下示例的编号、路径、结论与返回数字均为假设，不是本会话的可调用范围或验证记录；必须按当前历史替换：

```json
{
  "ranges": [
    {
      "fromRef": "m2",
      "toRef": "m5",
      "title": "认证方案调查",
      "summary": "结论：认证入口位于 src/auth.ts，当前使用 session cookie。已检查 src/auth.ts 和 src/middleware.ts；集成测试尚未完成，仍需验证过期 cookie 行为。"
    }
  ]
}
```

字段规则：

- `fromRef`：当前视图中的起始消息，包含。
- `toRef`：当前视图中的结束消息，包含。
- `title`：非空单行标题，最多 80 个字符，不含控制字符或连续三个及以上的连字符。它会出现在 block 头或未来的索引行中。
- `summary`：替代整段原文的长期摘要；不是给工具看的临时说明。
- `ranges`：一个或多个范围。范围之间不能重叠。

可以在一次调用中提交多个独立主题：

```json
{
  "ranges": [
    {
      "fromRef": "m2",
      "toRef": "m4",
      "title": "配置调查",
      "summary": "配置入口是 config.toml；阈值由 src/core/config-parse.ts 解析。当前未修改配置。"
    },
    {
      "fromRef": "m7",
      "toRef": "m9",
      "title": "测试结果",
      "summary": "src/core/context/nudge.test.ts 的相关测试已通过；端到端测试尚未运行。"
    }
  ]
}
```

批量调用是原子的：所有范围先统一校验，任一范围失败时整次调用不生效。一次调用不能依赖同一调用中刚创建的 block；超过配置的 `max_ranges` 时分批提交。

## 编写 title 和 summary

`title` 要让未来看到索引行时能立即识别主题，例如“上下文 nudge 边界分析”，不要写“历史记录”或“之前的内容”。

`summary` 必须让未来的 agent 在没有原文时仍能继续工作。优先保留：

- 目标：这段历史解决了什么问题。
- 结论：已经确定了什么，以及依据是什么。
- 路径和符号：关键文件、函数、配置键、命令或错误文本。
- 决策：采用了什么方案，放弃了什么方案，为什么。
- 验证状态：哪些测试、构建或检查已经运行，结果是什么。
- 未完成事项：哪些内容仍是假设、待确认或失败。
- 后续动作：继续工作时首先应该做什么。

可以使用下面的内部结构，但不要为了格式而丢失信息：

```text
目标：...
结论：...
关键证据：...
关键路径/符号：...
验证：...
未完成/风险：...
后续：...
```

禁止：

- 把推测写成已确认事实。
- 把“计划执行”写成“已完成”。
- 删除失败原因、保护条件或尚未验证的边界。
- 只写“已处理”“测试通过”这类无法支持后续工作的空话。
- 把整段原文复制进 summary，导致摘要没有空间收益。

## compress 失败后的处理

失败后不要原样重复同一组参数。先读取错误中的范围、ref 或 block 信息，再重新查看当前视图并修正：

| 错误类型 | 修正方式 |
| --- | --- |
| ref 不存在或已过期 | 重新读取当前可见的 `[mN]`，重新选择起止 ref。 |
| 起点晚于终点 | 让 `fromRef` 使用视图中更早的消息。 |
| 触及末尾保护区 | 将终点往前移；不要强行覆盖。 |
| 包含首条用户消息 | 将起点移到该消息之后。 |
| 工具调用与结果未成对 | 扩大范围，同时包含调用和对应结果。 |
| 部分覆盖已有 active block | 使用 block header 作为边界完整覆盖它，或完全避开它。 |
| ranges 重叠 | 拆成互不重叠的主题范围；一次调用中不要依赖新建 block。 |
| 没有新的可压缩内容 | 选择尚未被已有 block 覆盖的消息，或扩大范围。 |
| 范围太短、低于压缩阈值 | 纳入更多可安全总结的同主题历史；没有合适内容时暂不压缩。 |
| 摘要收益为负 | 缩短 summary，或把更多同一主题的历史合并进范围。 |
| 超过最大范围数 | 分成多次调用；每次仍需使用当前有效 ref。 |

错误消息包含当前实现的边界指导；以错误和当前视图为准，不要用记忆中的旧编号重试。

## 成功后的状态

成功结果是简短的状态确认，例如：

```text
上下文压缩：已压缩 4 条消息为压缩块 b3：认证方案调查，约回收 1200 tokens
```

成功后：

- 记录新 block ID（如 `b3`），但不要把本轮返回消息当作新的原文上下文。
- 状态已经保存；新的折叠视图在下一轮上下文变换后生效。
- 不要重复调用来确认成功，也不要在本轮假设原文已经从视图消失。
- 工具返回的是状态确认，不包含 summary 正文；需要结论时应依靠自己写入的 summary。

## 调用 decompress

参数只有一个 `blockId` 字符串：

```json
{
  "blockId": "b3"
}
```

调用前先确认 block ID 来自当前上下文或工具返回。`decompress` 有两种行为，由工具根据 block 状态自动选择；没有 `mode`、`restore` 或 `recall` 参数。

### active block：restore

active block 会被恢复为原始历史。工具会：

- 将 block 标记为 consumed。
- 在下一轮视图中停止折叠该范围，使原始消息重新出现。
- 当前轮不会立即注入原文；在下一轮之前不要引用“已恢复”的原文。
- 检查恢复后的上下文填充率；超过解压阈值时拒绝恢复。

成功结果类似：

```text
上下文解压：已恢复压缩块 b3 的 4 条原始消息，约回胀 1200 tokens，下一轮上下文生效——本轮请勿引用其原文。
```

如果恢复因上下文过满而失败，先压缩其他独立片段腾出空间，不要反复恢复同一个 block。

### 终态 block：recall

如果 block 已被更大范围消费、已经恢复过，或已经 stale，调用会进入只读 recall，而不是再次恢复原文：

- 返回仍保存的 summary。
- 不修改状态，也不改变当前视图。
- stale 表示原范围校验失效；工具会附失效提示，只能召回摘要，不能通过该 block 恢复原文。
- 返回内容可能被长度上限截断，不能假设包含原摘要的每个细节。

因此，`decompress` 并不总是“恢复原文”：

```text
active block  -> restore，下一轮显示原始消息
终态 block     -> recall，只读返回保存的摘要
```

## 常见误区

- 不要把 `mN` 当作跨轮次稳定 ID。
- 不要把 `bN` 写成普通数字或凭记忆猜测。
- 不要只压缩工具调用而留下对应结果，或反过来只压缩结果。
- 不要部分覆盖 active block。
- 不要把多个互不相关的主题塞进一个 summary。
- 不要在 summary 中删除未完成事项和验证状态。
- 不要在压缩成功后立刻引用下一轮才会生效的新视图。
- 不要把终态 block 的 recall 当作原文 restore。
- 不要并行执行会修改压缩状态的 `compress` 与 `decompress`。
