# Compress Usage 技能

compress 把连续历史压缩为摘要块，decompress 按块恢复。本技能提供两个工具共享的心智模型与使用策略。参数形态与返回值以各工具 description 为准；调用失败时服务端返回的中文错误是操作手册，按提示修正后重试。

## 概念模型

- **行号（ref）**：每条可见消息以 [mN] 前缀编号。行号是当轮视图的地址而非序号，每轮重新编号——只引用当前可见消息行首的编号，不凭记忆编造，不跨轮复用。
- **压缩块（block）**：bN 是块在会话中的持久编号。活跃块显示为 [Block bN · K 条] 块头加摘要；被更大范围消费的旧块只剩索引行 --- bN: <title> ---。
- **端点规则**：两个端点都必须当前可见，起点在终点之前；端点落在块头上将消费整个块（部分重叠被拒绝）。compress 的 toRef 为排他边界——传入某条消息之后的 ref 才会包含该消息；nudge 给出的可压窗口两端均为包含边界。
- **保护边界**：末尾保护窗与最后一条用户消息不可压；会话第一条用户消息永远不可压；收益不足的短段会被幻影门拒绝——选择更长的段。

## compress 策略

**分段要点：**

1. 重要信息不压缩：当前任务、关键决策与约束、文件路径、未完成验证的结论，都排除在压缩范围之外。
2. 按用户请求与任务委派边界分段：一个范围只覆盖一个主题，每块单独设 title。
3. 保留当前任务相关的最近上下文：与当前工作紧密相关的最近对话不要压缩。
4. 一次调用批量提交多范围：用 ranges 数组一次提交多段，减少工具往返。

**批量提交规则：** 同次提交的范围互不重叠；先全校验后统一生效——任一非法整次拒绝并指明第几个范围；不得消费同一次调用内刚创建的块；单次最多 max_ranges 个，超限分批提交。

**title 写法：** 不超过 80 字符、单行、不含 "---"。它日后作为索引行 --- bN: <title> --- 展示——要让未来的自己一眼认出这块内容。

**summary 写法：** summary 将永久替代整段原文。保留关键决策、结论与文件路径，确保后续工作无需回看原文。写之前自问：原文消失后，这段摘要够不够支撑后续工作？

## decompress 策略

**何时恢复：** 仅当摘要给不了你需要的确切细节（原始代码、完整报错、文件原文）时。恢复会回胀上下文——恢复最小的必要块，不为"可能有用"而恢复。

**两种结果：**

- 活跃块（带块头）：原始消息在下一轮上下文完整恢复，ToolResult 只回一行确认——不要在调用后的同一轮里引用原文内容。
- 旧块（仅剩索引行）：立即返回该块的完整摘要，上下文不变。

**失败处理：** 预估回胀超水位时调用被拒绝，错误信息给出替代指导（先压缩其他段腾空间）；blockId 不存在时错误信息列出当前可用块号。不要与 compress 并行调用——两者都修改压缩状态，可能冲突。
