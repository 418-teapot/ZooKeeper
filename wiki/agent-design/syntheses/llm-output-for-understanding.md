## Overview

> 优化 LLM 输出，不只是让回答更短，而是让读者更容易理解、执行和检查。文字可以用受控表达减少歧义；结构、变化和动态过程则可以用图表、交互网页或定制视频解释。选择依据是理解任务，而不是输出形式是否显得高级。

## Details

### 优化表达，而不是只压缩长度

缩短回答可以减少阅读量，却也可能删掉执行条件、关键步骤和必要解释。更好的目标是保留充分信息，同时降低理解负担：[有效上下文的构成](context-engineering/concepts/context-anatomy.md)强调输入应最小而充分，输出设计则要让这些信息容易被读者使用。

ASD-STE100 Simplified Technical English 是一种受控自然语言和技术文档国际标准，最初用于帮助不同语言背景的人员理解航空维修文档。它为技术英语提供词汇与写作约束；用于 LLM 时，可以把其中适合当前任务的原则明确写进输出要求：

- **同一概念使用同一术语：** 不为了文风变化轮换名称，避免读者把同义表达误认为不同对象。
- **优先主动语态：** 明确谁执行什么操作，少用隐藏执行者的被动表达。
- **一个步骤安排一个操作：** 将连续动作拆成可逐项执行、检查的步骤。
- **使用短句：** 拆开复杂从句，但保留条件和因果关系。英文程序性指令可采用每句不超过 20 个词的约束，不把它扩展成所有文本的统一要求。

例如，操作说明可以把“连接设备并启动服务，然后检查状态”拆成“连接设备”“启动服务”“检查服务状态”三个步骤。重点不是机械切句，而是让每一步的动作和检查对象清楚。

### 按误读成本选择约束强度

严格技术写作与 STE-flavored 写作共享清晰、一致的目标，但对词汇和表达自由度的要求不同：

| 场景 | 选择 | 重点 |
|------|------|------|
| 操作指南、API 或工具说明、错误信息、Agent 间指令 | 严格技术写作 | 固定术语，明确执行者、条件和单步动作 |
| README、长技术解释、产品说明、FAQ | STE-flavored | 保留短句、主动表达和术语一致，允许必要的解释与自然措辞 |
| 简单问答 | 直接清晰地回答 | 不为套用规范增加额外结构 |

“约 80% ASD-STE100”表达的是放松约束、保留清晰风格的取向，不是精确的规则覆盖率或合规分数。STE-flavored 也不是正式合规等级。需要声称符合 ASD-STE100 的技术英语，应按完整官方标准检查，而不能只依赖提示词中的模式名称。

[Agent 工具设计](agent-design/concepts/agent-tool-design.md)要求描述明确用途、参数和失败行为；受控表达可以落实这些要求，例如固定参数名称、拆开连续动作、直接说明错误后的修正操作。

在内容生产和检索知识库中，可让产品说明、FAQ、API 文档沿用同一套术语，避免同一对象在不同页面中随意改名。这里的应用目标是语义一致、便于理解和抽取，而不是增加关键词数量。

可直接使用的风格要求：

> 用 STE-flavored 风格解释以下技术内容：同一概念始终使用同一术语，优先主动表达，拆开复杂长句；操作步骤每步只包含一个动作。保留必要条件、例外和专业术语，不为缩短文本删掉关键信息。

### 让输出形式匹配理解任务

当困难来自关系、变化或动态过程时，继续改写文字未必是最有效的办法。可以让 LLM 生成更适合观察和探索的表达形式：

| 输出形式 | 适合解释什么 | 使用方式 |
|----------|--------------|----------|
| 受控文本 | 定义、规则、步骤和精确条件 | 使用一致术语、短句和明确动作 |
| 图表或图像 | 结构、依赖、流程和空间关系 | 把对象及其关系放在同一视图中 |
| 交互式 HTML 页面 | 参数变化、状态转换和方案比较 | 用滑块、切换项或动画让读者观察变化 |
| 定制讲解视频 | 连续过程和需要逐步建立的直觉 | 用画面与旁白组织解释顺序 |

例如，解释学习率时，可以让 HTML 页面提供滑块，展示不同学习率下的下降轨迹；解释算法过程时，可以用动画或视频逐步展示状态变化。

这些形式不是固定的优劣阶梯。简单问题用几句话即可；复杂问题可以组合文字、图表和交互。生成要求应先说明读者要理解什么，再指定形式，避免把视觉丰富当作解释充分。

### 把定制产物当作临时理解工具

随着模型承担更多具体执行工作，人的工作可能更多转向设定目标、监督过程和理解结果。输出因此不只是最终答案，也可以成为帮助人检查和理解工作的工具。

当代码和内容生成成本降低后，可以为一个具体问题临时制作交互网页、图表或讲解视频。这些 large、custom、discardable artifacts 不必都成为长期维护的产品：针对当前读者和问题生成，完成理解任务后即可丢弃。

使用这类产物时，先明确要回答的问题，再检查它是否真正说明了关键关系、步骤或变化。是否保留取决于后续使用价值；“可丢弃”指维护生命周期短，不意味着内容可以免于检查。
